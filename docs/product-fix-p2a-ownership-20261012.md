# W02 原生文字与源轮廓归属

状态：本案例重复输出已修复；LibreCAD 原生保存复读仍有验证缺口。版本保持 `0.3.0-dev`。

## 根因

首次失败发生在源覆盖与内容归属阶段。`text_output_contract.decide_text_output` 将文字输出资格与源轮廓抑制资格分开；`replacement_safe=false` 仍可输出 TEXT。
Responsible 的强墨迹包含约 33 px 宽的英文连笔。逐字分割将其判为跨字符格笔画，保留旧保护框；旧框又没有覆盖完整源词。
整页清晰数字图使用 254 阈值，保留的抗锯齿边缘还会连接两行英文。逐字遮罩未拥有完整载体，剩余轮廓成为可见 TRACE_TEXT_SYMBOL，随后与 TEXT 同时导出。预览如实显示了重复对象。

225 的源支持含 Discipline 的末端和 Responsible 的部分笔画；226 含 Responsible 的相邻笔画。两者的强源像素均属于已验证文字行，不共享表格线或其他结构。
处理后二值图中，两个轮廓分别有 301、24 个源支持像素。句柄只用于记录匹配结果，不参与规则。

## 产品修改

- `app/ocr/ocr_layout.py`：在现有单元格行归属中保留各行完整强墨迹掩膜。只有完整单元格源证据通过时，允许英文连笔免于强制逐字断开；覆盖、边界、邻近笔画和手写保护继续执行。原显示 quad 不变。
- `app/ocr/ocr_fast.py`：传递上述内部整行验证状态，保留其他检查。
- `app/geometry/content_ownership.py`：补全已验证文字的完整处理后连通载体。每个强源像素必须已有合格文字行归属；共享 LINE、logo、签名或不确定内容、触及单元格边界的载体不补全。不裁断轮廓，不清空区域。
- `app/geometry/optimized_trace.py`：使用原灰度强墨迹取得行证据；在现有内容仲裁之后、语义轮廓生成之前补全归属。后续仲裁否决某行时，仅保留其他仍合格行的证据。
- `app/core/processing.py`：增加 `text-carriers-v1` 缓存算法标识，保留旧缓存。
- `tests/test_table_text_layout.py`：增加真实整行载体和共享结构、未归属墨迹、不确定文字的保护用例。

没有修改三行内容、行距、字体、数字复核或 DXF 写入器。没有根据句柄删除规则。
