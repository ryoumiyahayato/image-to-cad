# P5 竖向尺寸文字

指定缺陷可关闭。版本保持 `0.3.0-dev`。

RapidOCR 将纵长裁片转成水平文字后识别，再执行 0/180 分类，但输出检测框没有同步阅读顺序。`_candidate_from_quad` 用原框短边计算方向，得到 0°。已有 `native_text_placement` 因此把 23×108 px 当成水平行，产生大字高和极小宽度系数。DXF 写入器没有覆盖一个原本正确的方向。

`app/ocr/ocr_recognition.py` 在正常识别 pass 内新增局部阅读方向复核。仅检查未人工复核的纵长 ASCII 多字符候选。分类置信度须达到 0.95，选定方向识别须保持原文本且达到 0.90；原方向或反方向同样可靠时不调整。通过后循环重排 quad，由现有坐标变换、字体度量和 TEXT 写入路径计算布局。不修改文字、OCR 置信度、bbox 或源替换权限。

`app/core/processing.py` 更新算法缓存标识，避免正常入口复用旧布局。产品版本不变。没有修改 P4、数字复核、中文墨迹收紧或表格行距逻辑。
