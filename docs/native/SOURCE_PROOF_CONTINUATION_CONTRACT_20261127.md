# Complete upstream source-proof continuation (Issue 61)

This contract is frozen before implementation of the second checkpoint boundary.
The first ordinary run and checkpoint v1 remain unchanged negative evidence:
their fresh cold source audit failed. This contract neither changes a coordinate
nor adds a numerical tolerance. It does not claim deterministic uncached replay.

## Explicit evidence boundary

`source-stage-checkpoint-pre-attached-v2` retains the complete pre-attached state
and adds `historical_saved_proof`, schema
`historical-complete-source-proof-capsule-v1`. The capsule includes the original
saved DXF, complete source-object sidecar, cold proof, export manifest and worker
publication manifest. The export/publication bind the exact saved DXF, sidecar,
cold proof and every reused source artifact; the worker request, original image,
ROI/DPI/orientation/units, old assembly and producer closure are already bound.
The entire historical export is verified when constructing the new capsule.
Only artifacts needed for this complete upstream responsibility are reused.
The old global source PASS is never an authorization input.
The historical DXF is read only for independent proof/content/resource audit;
the source assembly remains the sole construction input. V2 records
`historical_DXF_read_for_proof_validation=true` and
`old_DXF_entities_used_to_construct_output=false`; it does not repeat v1's
literal no-DXF-read claim.

The historical attached stage is removed using its own bound adoption and cold
check list, together with primitive checks for its explicitly added objects.
Every remaining historical source check is retained, including neighbor,
retirement, manifest, text, circular and composite responsibilities. The rule
does not select the currently failed object IDs or check types. Every upstream
object needs historical source-proof coverage. A historical failed/missing
upstream proof cannot be promoted by this mechanism.

V1 is not retroactively upgraded. New capsule bytes, validator code, source-proof
reviewer and continuation executor hashes require a newly created manifest and
newly captured ordinary job. The historical runtime binary/CPU information that
was not recorded remains explicitly unknown.

## Current saved result obligations

The new module `source_proof_continuation.py` emits
`source-proof-continuation-saved-audit-v1` at
`evidence/source_proof_continuation_audit.json`. It must independently establish:

1. The complete v2 manifest/capsule/source/request/artifact closure is valid.
2. Current upstream source objects exactly equal the historical complete state;
   actual persisted entities, recursive block members, XDATA, REVIEW, styles,
   layers, line types and units exactly equal the projected historical saved
   objects. Database handles may be different and must be mapped from unique
   actual identities. Neither one-level snapshots nor sidecar equality alone
   can establish this obligation.
3. Current actual native geometry passes direct original-pixel sampling with
   the unchanged existing line/curve sampling rules. Source/geometry/frame or
   identity mismatches remain hard failures.
   The complete fresh source-check responsibility multiset must equal the
   full retained historical nonprimitive projection, independently repeated
   current primitive samples and actual current attached checks. Unknown,
   additional or missing responsibilities fail closed. Current primitive
   results must also exactly match the fresh cold primitive rows; the
   continuation cannot suppress a current actual-pixel failure.
4. Every actual repeated segment is enumerated again. A historical same-owner
   allowance is usable only after exact complete current native-path equality,
   unique old/current handle mapping, exact protected segment-index matching,
   actual repeated finite segments, and original-ink source-edge checks. Any
   cross-owner, new, missing or changed responsibility stays rejected. Old
   handle values and global duplicate counts never grant an exemption.
5. The current attached stage is EXECUTED and its complete current plan,
   all-prior contacts, joint numerical replay and actual saved-target audit are
   valid. Every actually adopted target must pass its raw-ink/source gate;
   rejected candidates retain their failed source results. Zero adoption never
   turns candidate ink failures into successes.

Portable font and license bytes beside the actual output are checked against
the original exported resources. Complete current written receipts are rebound
to unique actual handles, kinds, native types and block members. Upstream
receipt payloads remain exact except for database handles. Font source-location
provenance may move while the names, content hashes and rendering definitions
remain bound. Historical source-check schemas validate their required proof
bodies and accepted branches; a true outer result with empty or failed inner
proof is not reusable. Recorded competing raw readings and rejected layout
attempts remain intact.

The historical proof is reused as a complete source computation with unchanged
inputs, producer closure, finite responsibility and recorded witnesses. Its
individual diagnostics are not refitted or selectively ignored. Current native
geometry and source sampling are independently checked. Every reused proof is
identified by its full payload digest and the closed saved-source provenance.

## Fresh failure and effective publication gate

The existing `cad_io.cold_audit` and all original upstream producer bytes remain
unchanged. `evidence/cold_audit.json` is always generated normally and retained
with its actual fresh result, including failures and all repeated segments.

Only an explicitly captured v2 source checkpoint can select
`SOURCE_CHECKPOINT_PROOF_CONTINUATION`. The new audit records the original fresh
cold path/SHA/verdict, complete historical proof projection, current exact saved
content checks, direct-pixel checks, all current duplicate/retrace bindings and
current attached-stage evidence. It emits a separate effective audit view for
the ordinary current-input quality review; it never rewrites the fresh report.

The pipeline report and `source_stage_continuation.json` record the selected
mode and new saved-audit file SHA. Worker publication, committed-result recovery
and export independently validate that explicit mode and the referenced current
saved result. They cannot publish by observing an isolated PASS boolean or by
discovering an unrequested continuation file.

## Required discriminating checks

Reject changed source/frame/dependency/capsule bytes; missing or failed old
upstream proof; changed source responsibility or finite composite member;
changed nested block, XDATA, resource, REVIEW or unit; missing/new formal
objects outside current stage adoption; actual off-ink geometry; old allowance
with changed owner, native segment or source edge; cross-owner duplicates;
missing/not-run/failed current attached stage; stale fresh audit or continuation
gate; and use of v1 or a gate without explicit captured v2 authorization.

Validate the actual first-run saved draft through the new local reviewer before
starting a new ordinary job. Its original fresh FAIL remains part of the record.
