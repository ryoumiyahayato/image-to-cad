# Issue #59: finite attachment ink and prior-contact contract

This implementation contract is frozen before the first new ink gate runs.
It builds on A at `2010e6da30b4aa9812ec4730d338edf76fca6b2d`.
It does not change the strict numeric replay policy owned by #60. Main remains
the 436-object baseline; this branch is an independent experiment.

## Observable CAD boundary

The supported model is an observable finite centerline attachment. A complete
guest ends at its uniquely source-supported intersection with a complete finite
host. Ink is explained by constant-width round capsules around the actual saved
straight segments (their union supplies round joins; internal vertices are not
new stroke endpoints). Physical pen order and subpixel travel hidden entirely
inside the independently bounded junction are **NOT_IDENTIFIABLE**.

Before examining results, the CAD convention is fixed: an extension wholly
hidden in the finite host thickness and the guest's ordinary round cap, with no
independent outer source arm or new contact, normalizes to the same finite host
intersection. This is a declared observable representation convention, not a
claim that all physical real-valued endpoints are uniquely recoverable. Any
connected black cell outside this independently established junction envelope
cannot be normalized away, even when thinning creates no extra graph arm.
It remains an unexplained residual or an observable boundary competitor.

No new geometry is generated by this gate. A different visible endpoint needs
a separately justified complete decomposition, not extension to a pixel extreme.

## Fixed model and resource choices

- Use the unchanged source and existing threshold. A changed source requires
  rebuilding its graph and formal owner. Actual finite guest/host geometry,
  producer bytes and the source crop are bound to each receipt.
- Measure width on original independent arms at the existing finite observation
  spans **6, 8 and 12 px**, stopped at the next graph node. Project each observed
  sample onto its actual finite native segment. A terminal native segment shorter
  than the existing **4 px** direction minimum is outside this first model.
- A normal section extends at most **12 px** each side, the existing finite core
  extent resource bound. It needs original white on both sides, at least two
  distinct valid sections, and a nonempty common half-width interval. Reaching
  the scan limit is missing evidence, never a permissive default width.
- Exclude contaminated sections: another candidate/owner centerline must be
  farther than twice the measured upper half-width plus the pixel-cell diagonal
  half-span. This is a conservative exclusivity condition, not added cap slack.
  Source node/core pixels and the pixels under endpoint review do not calibrate
  their own width. The actual exclusions and all first white cells are recorded.
- A pixel owns its closed unit square. For a black cell, the capsule must meet
  that square; for a white cell, there must remain a point outside the union.
  Width lower bounds use the minimum cell-to-axis distance; upper bounds are
  strict, from the maximum distance of a first white cell to the axis. No 1.5 px
  fitting allowance, 3 px free-cap allowance or extra raster tolerance is added.
- A complete hypothesis uses one guest half-width and one host half-width.
  Enumerate the finite black-cell distance events to find coherent feasible
  pairs within the independently measured intervals. Patch whites may only
  shrink feasibility. Never combine per-pixel choices from incompatible models.
- For each white cell, a corner, edge midpoint or center strictly outside both
  capsules proves it is not completely painted. If these fixed nine witnesses
  cannot establish this, the model remains pending; it does not erase the white
  cell. This conservative sufficient test is not an exact claim about all
  possible cap shapes.
- Start the observation radius from the independently bounded round cap and
  finite host thickness projected along the actual guest direction, plus a
  one-cell border. Double the radius if an unexplained connected residual exits
  the window. The existing **240 px** component bound is a resource limit only;
  a cropped/resource-limited observation remains pending. Explained finite
  shaft corridors may exit the observation window and are explicitly recorded.
- Keep all original black components and original white components/holes in
  the ledger. A disconnected neighbor is not a guest continuation. Genuine
  white gaps and the left stroke's real free tail remain unchanged.

For an unexplained outward residual, evaluate source-supported finite extension
events along the actual terminal direction using the same width constraints and
white tests. These are refusal witnesses only. No black point is automatically
promoted to a centerline endpoint. All finite observed graph directions and the
actual native terminal direction remain available, including disagreement.

## Status and joint adoption

`PROVED_TERMINAL` means complete responsibility under the observable convention
above. Other states distinguish boundary competition, unexplained source ink,
independent-width failure, unsupported local direction/model, observation
truncation and an actual source/contact contradiction. Pending is not proof that
the old finite geometry is wrong. Missing evidence is not a material block.

Run all three attached-end checks after fitting the entire joint component.
Store every receipt and all candidate geometry before applying the gate. One
unproved endpoint leaves the complete host/companion component pending; no subset
is manually copied from the old four-object DXF. Existing direction, free-cap,
white-cell, duplicate, external-source, text and new/new-contact gates remain.

The added prior-native-contact gate examines actual exported graphic members of
every retained object. It distinguishes an independently source-proved finite
point contact, an unsourced point and positive-length overlap. Relevant
unsupported curves remain pending; true conservative curve bounds may prove
separation, but endpoint chords never stand in for curve contact tests.

belong only to fixtures; private coordinates, object IDs, file names and a desired
adoption count are not production selection rules. The real three endpoints
start as source pending and may pass only by this new evidence. No new Windows
build, GUI exercise or main merge is part of #59's parallel assignment.
