## 圈内字：实际阻塞和共同流程

原始字符裁片和全部原识别输出先读回，阻塞在严格字符采用门：

| 位置 | 保留的原始读法 | 原拒绝原因 |
| --- | --- | --- |
| LAUNDRY 右端 | Tesseract `D / D`，PP-OCR `0 / 0` | Tesseract 没有达到完整字符置信门，且两引擎未形成唯一一致结果 |
| BEDROOM 远端 | 两引擎均读到 `E`，各自保存两种输入视图 | Tesseract 完整字符置信门未过；另一引擎的高分不能单独代替共识 |
| 第三验证圆 | Tesseract `D / D`，PP-OCR `D / 0` | PP-OCR 未达到完整字符置信门，且原竞争读法仍存在 |

保留原双引擎规则，增加正式的 **`SAME_SOURCE_FROZEN_GLYPH_REFERENCES`** 路径。它复用同次任务、同一原图已经可靠识别的字符，而不是从旧 DXF 或目标名称取答案：

1. 先冻结来源字符库。可用来源只有原先严格双引擎通过的圆内字，以及整行原始证据严格重放通过后、两引擎无争议的完整单字符。每一参考字重新绑定原图完整墨迹、识别文件和来源域；重叠来源只能算一个见证。
2. 候选必须是目标原始输出中确实出现的完整单字符，至少与 **两个互不重叠的原位置**相符。新补出的字不回填字符库，避免相互证明。
3. 检查所有原始竞争单字符及来源库中可用的其他类别。缺少竞争字的可靠参考不能当作排除证据；任何未能比较的非空多字符读法也阻止采用。
4. 使用已有原字形比较规则，在有限的栅格采样偏移下比较原墨迹；竞争读法必须在这些比较中全部失败，或存在可靠的稳定拓扑差异。没有降低 OCR 置信门，也没有修改原像素、填白缝或生成新字形。
5. 保存后的冷读重新读取目标、参考来源、原始识别和原图像素，重建冻结字符库并重新作竞争判定；不能只信采用记录的 `accepted` 字段。

最终冻结库有 94 个独立原字形，来自 21 处原始严格圆字和 13 条可靠整行。逐字符核验排除 4 个被邻笔污染的锚点，保留同一行中仍可靠的完整 `0` 等其他字形，不因一个污染锚点丢弃整行。

T1 的真实 `D / 0` 分歧继续保留，`0` 和可用的 `O` 原字形均经过竞争排除。T2、T3 同样通过这条来源核验路径。三个目标之外，同一规则自然升级另三处 D、J、F，**附带结果单列，不替代目标验收**。六个升级对象的实际 `TEXT`、位置、大小、原圆几何和原始采用依据均已保存后冷读通过；没有叠放第二个圆或重复字符。

生产实现主要在 `circle_glyph_resolution.py`、`circle_character_recognition.py` 与 `circular_marker_adoption.py`；普通流程和保存后字符来源审核使用同一证据契约。原字形比较仍复用 `source_glyph_equivalence.py`。

## LAUNDRY：传递已有末端观察

先查原始路径观察，确认目标末端的墨迹与连接核心已经存在；遗漏发生在完整接触路径的表示与组装传递，不能将它描述为原观察不存在。

共同修正由 `text_contact_geometry.py` 传递原始末端核心、到达路径和邻接分支前缀，再由 `circle_endpoint_contacts.py` 重放。只在有限原始核心内、两个相反方向的可靠圆边分支能确定同一个圆端口时恢复连接，并检查：

- 原末端与重放路径同源，圆端口唯一，没有其他合格归属或竞争接头；
- 新段经过的每个闭像素格都有原黑墨；真实白条不能被距离吸附跨越；
- 原长曲线全部旧顶点、顺序、宽度和 bulge 保留，新尾段追加在同一个 `LWPOLYLINE` 中；
- 保存后从原始来源图重新构建并核对实际圆边接触，不仅重读证书自述。

原先 **5.362678 px** 是旧端点到圆边的径向缺口；实际沿可靠端口恢复的尾段长度为 **5.711458 px**。两者是不同测量。`CONTACT-f072ebaf392c` 从 **31 → 32 顶点**，没有独立尾段实体，整条删除后不会留下该尾段。原短直段门保留为回退；本批不是把长度常量改到 5.36，也没有按最近距离吸附。

真实白缝、旧正确圆字与近邻竞争端口/圆归属纳入针对性保护；竞争失败保留待修。普通整区其余正确长曲线保持，未借本次接头扩大周边网络恢复。
