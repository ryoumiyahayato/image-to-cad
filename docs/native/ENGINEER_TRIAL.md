# 工程师发现问题试用

当前状态：**NOT_RUN — 尚无工程师参与，无实际修图时间或最高成本实测位置。** 自动检查、代理CAD操作和工程师工作分别记录。可以立即准备和开始发现问题的试用；它不等于正式采用。

## 交付准备

私有试用包应包含同一冻结区域的主DXF、原图、必要字体及许可证、来源与待修索引、打开说明、[JSON记录模板](ENGINEER_TRIAL_TEMPLATE.json)和可写工作目录。记录源码提交、输入/配置/主DXF的SHA-256、区域范围、CAD完整版本和字体。真实图纸、OCR缓存、字体二进制及逐对象坐标不进公开GitHub。

开始前填写模板中的空字段；不要用旧图或已被修正的报告替代本轮主文件。改后文件有独立哈希；旧审核仍仅绑定原主文件。操作步骤见[打开说明](OPEN_IN_CAD.md)。

## 真实修图工作与计时

| 工作类别 | 计入人工修图的内容 |
|---|---|
| 查找遗漏 | 对照原图寻找漏墙、漏线、漏字、漏门和符号；逐区搜索与判断 |
| 补绘对象 | 所有遗漏内容的重画、成组、尺寸与关系恢复 |
| 修正文字与连接 | 错字/缺后缀/行序/字号/布局，交叉或连接关系与短枝 |
| 清理不合理对象 | 重复线、残片、错误块成员和不合理对象；不能删掉真实短划或抹平白缝 |
| 处理格式问题 | 字体、单位、图层、格式往返、独立消费者和打印修正 |
| 最终核查 | 整区域复核、保存退出重开、邻居保护与交付检查 |

每段工作记录开始/结束、暂停、实际操作秒数、类型、位置（像素区域或CAD位置）、目标对象、问题、修法和输出文件。计时不得互相重叠；离席时间单列，必需的文件等待也单列。保留原始时间记录，最后按类别汇总，不把“没做”写为0秒。

同一失败需要跨多个类别处理时，分别记录时间并共用同一failure_id。最高成本位置按真实累计时间排序，同时保留尚未解决的项目；不要预先把PANTRY、C07/C08等当作“最高成本”结论。

## 发现问题试用的结束条件

工程师交回实际修过的文件、时间记录、优先失败位置和尚未完成事项。只要记录真实，即使尚未达到同等最终质量，也可以结束一次发现问题试用并指导下一轮算法；结论写 `DISCOVERY_COMPLETED_NOT_ADOPTION`。若未参与，状态保持 `NOT_RUN`。若环境不完整，则记录 `ENVIRONMENT_BLOCKED`，不能冒充算法或工程师失败。

## 正式“修图不超过手画一半”另立验收

正式比较必须用**同一完整冻结区域、同等最终内容与质量**：一组从原图手画，一组修正当前生成DXF。两组都必须包括全部补绘、文字/连接纠错、格式处理和最终核查。事先写清哪些内容必须恢复及允许误差，再由工程师确认最终质量相等；若质量不等，不计算通过结论。

保存工程师、CAD版本、字体和标定条件，记录先后次序及熟悉图纸带来的学习影响。八项预选删移操作只能说明那些编辑动作发生，不能作为完整区域的时间分母或分子。

仅当两组最终质量均经核验且时间记录完整，才计算 `repair_active_seconds / redraw_active_seconds`；比值≤0.5才满足时间条件。单次发现问题试用、脚本耗时、估计工时、模型生成时间均不得替代该比较。正式采用还需对应对象完整性及兼容条件成立。
