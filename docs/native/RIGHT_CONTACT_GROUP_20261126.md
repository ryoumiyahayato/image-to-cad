## 完整路径实际被什么阻塞

旧普通流程的实际停止点是第三处斜划交点的 `CONTACT_PAIR_OR_COMPETITION_NOT_UNIQUE`。局部方向探索跨过相邻接点时，没有利用已经能独立证明的连续方向，因而把不属于同一连续笔画的分支方向纳入当前路径的最坏偏转。旧最坏偏转 **36.86989764584403°**，超过原 **20°** 门槛；“没有已采用路径”只是这个判断的后果。

`structure_contact_geometry.py` 增加有限、无循环的相邻方向证明：每一轮先核对全部端口；只有在正反方向最坏情况下仍胜过全部竞争、并满足原 **18°** 余量的配对，才能供下一轮使用。不改写原图或原 graph pairing，不按起点或预期终点丢弃竞争，不用相互未决的配对循环证明自己。该位置在充分来源约束下最坏偏转为 **17.18958455615368°**，正反竞争余量分别为 **72.81041544384632°、53.796741055316545°**，原阈值保持。

继续向下还有有限承接线的阻塞：数字与承接线接触，把原来连续横线分为数段短 graph edges。新的有限来源延续根据已经正式存在的独立 LINE，逐接点证明唯一同向墨迹并保存所有旁支；不能把短 graph edge 当成整根横线终点，也不能跨白缝或借近邻线补足。来源自由端的短帽补证复用既有原黑墨迹、白帽、支路和邻接门，保留原 **3 px** 有限端部约束，不修改全图骨架。

新路径抵达圆端口时还要与既有上方曲线分清责任。粗栅格端口可能同时包含两条来源充分的独立到达路径；程序重新核验每条外部来源前缀、同一接触核心与两侧圆环分支，排除尾段正长度重叠及内部交叉。在新尾段所有像素都有原墨迹依据时，沿用该共同核心已证明的圆端点，保持旧曲线全部几何，并把新尾段保存在新路径自身。没有最近距离吸附，也没有用临时短竖线代替完整对象。

最终来源边链与修改前独立查看的完整边链一致，字形侧环、三条斜划和附笔没有被吞入。正反追踪一致；最终保存起点落在实际圆边，终点落在实际有限承接 LINE 内部，承接线参数约 **0.25991172444630994**，垂距为 **0**。圆端口误差仅为浮点末位。定位节点、坐标和对象 ID 只在私有评价记录中用于定位和核验，不进入生产采用条件。

## 同一次普通流程中的完整短字符

普通流程先正式采用完整路径，再运行已有短字符阶段。字符阶段只接受本次实际采用且来源重放通过的路径与实际有限 LINE；未采用骨架、临时线或左侧文字实例不能提供责任。

原图 `$3` 等竞争读法原样保留。程序核对同一 OCR 观察、被争议的字符位置、共享核心、完整路径和有限承接线之间的来源关系，再评估去除独立图线责任后的字形。只对某一位置成立的图线解释不能拿去排除另一位置的字符竞争；较强的归属图像竞争也不能用原图共享笔迹来豁免。

右侧数字底部连接承接线，原始连通分量不等于一个独立字。分区保留完整字身、上方原始微环、短回笔、两个接触核心及它们之间的完整共享底段，所有原始自由端均保留。独立来源审核核对首字符 **74** 个、数字 **62** 个原骨架样本，没有缺失或补画。仅保留接触核心会切断字底，程序没有采用这种截断形式。

数字的单独 PSM10 空值保留；完整词位置佐证有专门条件和记录，不能称为“孤立单字符双引擎一致”。最终完整组采用 `S3`，不是复制左侧答案。两个成员具有不同来源字高和相对基线，用最少的两个真 TEXT 组成唯一实例图块；块内不含接线。右侧改字、整体移动和删除均不改左侧 S3 或 C07 字符。

### 固定局部补证的通用规则

新增规则仅复用已有完整分区及正式对象责任，适用于来源足够、但一个孤立读法仍发生非空弱竞争的组件：

1. 组件的完整字身、回笔、共享接点及原始自由端都保留，承接线与本组已正式采用的完整路径相互绑定；承接来源哈希、实际有限终点和字形两侧延续相符，没有未分配分支或竞争回笔。
2. 归属图整组、原图整组和组件模型都满足原严格门；组长等于完整组件数。原图与归属图固定 PSM7／13 的四份观察各为一个覆盖完整组的词，该组件位置全部保持同一原始字面。原图词读数须达到原 85 门。
3. 原 PSM10 必须是覆盖完整组件字框的单个非空字，字面不同且未达到既有强竞争门 85；条件仅由补证前的来源和原始观察推导。条件成立后只追加一次 PSM13，原像素、2 倍最近邻放大、12 px 外留白及任务 DPI 保持。
4. 新 PSM13 必须是一个同字的完整字框，读数至少 85；原 PSM10 非空竞争继续保留在组件竞争清单。空、弱、异字、不完整、新增强冲突或任一整词字位改变都继续 pending。没有把低分 `J` 当作空值，也没有以模型或另一实例答案直接放行。

原空 PSM10 的整词字位回退保持独立；新增观察不声称来自另一 OCR 引擎。执行前冻结条件计划，决策和冷重放分别从原证据推导合法 `[10]`／`[10,13]`，拒绝缺失、重复、无资格附加视图。冷读实际校验 PNG 像素、TSV 原文、字框、参数、DPI、模型输入／张量与补证文件，不用记录自报通过替代重放。几何、字框容差、布局门和公开输入字体均未更改。

无缓存入口的新 short-contact 观察通过 `record_engine_identity=True` 测量实际 Tesseract 程序与其报告的英文字库字节；没有隐式开启缓存。旧检查点和缓存保留原始 producer 身份，不用当前安装版本回填。纯 `[10]` 保持原契约；新增 `[10,13]` 冷重放要求两份原始元数据具有完整且一致的程序／字库身份，缺失或不一致明确拒绝。
