# Pre-attached source-stage continuation contract

This contract defines the explicit Issue #61 continuation boundary. It applies
to an explicitly selected, already completed source checkpoint. It does not
claim that an uncached fresh geometry run reproduces a historical CAD file.
The first v1 run and its fresh cold failure remain preserved. The current v2
boundary adds the complete saved-source proof described in
`SOURCE_PROOF_CONTINUATION_CONTRACT_20261127.md`; it does not upgrade a v1 packet.

## Boundary and input

The reusable boundary is the complete source state after short-contact text and
before attached-stroke discovery. It includes finite lines, wall boundaries,
door coverage and remaining intervals, every complete composite member, all
text and graphic source responsibility, upstream uncertainties and their raw
evidence. Reusing only LINE fits is insufficient.

The importer may derive this boundary from a completed ordinary assembly only
when its own attached-stage receipt identifies exactly the objects it added,
declares no retirement, and binds the entire preceding object list. Removing
these stage-declared additions is a generic stage projection, not selection by
case ID, coordinate, expected object count or CAD snapshot. The complete source
assembly remains the only construction input. V2 reads the historical DXF only
for independent complete content, resource and proof validation. It records
`historical_DXF_read_for_proof_validation=true` and
`old_DXF_entities_used_to_construct_output=false`. No historical CAD entities
are imported into the output.

The checkpoint schema is `source-stage-checkpoint-pre-attached-v2`. The manifest
binds unchanged source bytes and decoded pixels; full ROI, DPI, orientation,
page/frame and paper units; the complete finite upstream state and raw evidence;
the original completed-stage and worker producer identities; and the reused
code closure and runtime/resource dependency identities. Missing or changed
inputs fail closed. A new destination is required and original bytes remain
read-only.

`historical_saved_proof` adds five content-bound artifacts: the historical saved
DXF, source-object sidecar, complete cold proof, ordinary export manifest and
worker publication manifest. The entire historical export is checked when
creating the packet. These proofs bind every reused source artifact and cover
every upstream object. Only the previous attached stage's own declared checks
and primitive samples are projected out. Empty, unknown or failed upstream
proofs fail closed. A historical global PASS is not a substitute for these
complete proof contents.

## Code and dependency closure

All historical native producer files are compared to current files, except the
explicit attached-stage modules that always rerun and the pipeline orchestration
that is checked structurally. The pipeline proof compares all pre-existing
helpers/imports/constants, original entry arguments/defaults and the complete
pre-try preamble (including source, decoded gray image, ROI and DPI setup), plus
the complete fresh stage statement sequence through the last short-contact
append. Only the new optional selector and its exact mutual-exclusion guard
are removed from the historical projection. Reordering, changing or deleting
an upstream call, gate or assembly statement invalidates continuation. The
known local source dependencies outside the native directory are also bound.
The current continuation dispatcher, entry, worker, job manager and main entry
are additionally bound by their full file digests from checkpoint creation
through execution. An unchanged single geometry module is not sufficient.

Recorded historical runtime package versions, Python version and platform must
match the declared runtime closure. Current binary/resource identities are
captured and must remain unchanged through task capture and worker execution.
This includes every locked distribution's Python and native production code,
including same-version source edits, and the actual Python executable bytes;
interpreter cache files are excluded.
This does not invent unavailable historical CPU/BLAS binary-dispatch identity
or claim to solve all cross-platform deterministic recomputation. Model, OCR
language data and font resources are content-bound; checking their identity
does not execute recognition.

## Ordinary entry and new execution

The ordinary native entry accepts `--source-stage-checkpoint MANIFEST`. The task
manager verifies and captures it into that task, then the worker verifies the
captured bytes again using `captured-source-stage-checkpoint-v2`. The pipeline
explicitly reports
`SOURCE_STAGE_CHECKPOINT_CONTINUATION`, the source manifest digest, all reused
stages and downstream execution status. Failure emits a machine-readable
rejection receipt and does not silently fall back to fresh fits.

After restoring the complete upstream source state, the current pipeline always
rebuilds the original-source graph and runs the new attached ink, all-prior
contacts and joint numerical contract. Historical attached plans, adopted
objects and their source audits do not authorize this run. The ordinary native
writer, unchanged fresh saved cold audit, render and current-input review run
again. The original fresh cold report is retained byte for byte with its actual
result. A separate `SOURCE_CHECKPOINT_PROOF_CONTINUATION` audit binds the full
upstream proof to exact current recursive native contents, source payloads,
portable resource bytes, actual original-pixel samples and every current
same-owner repeated segment. All new attached responsibilities still require
their current executed stage and complete joint replay. The effective source
gate is explicit in the report, worker publication and export, and it is
independently re-audited at publication, committed recovery and export.

`source_stage_continuation.json`, schema `source-stage-continuation-execution-v2`,
records what actually ran, including the saved-proof audit SHA. Upstream reuse does
not become a source PASS for new objects. Zero current adoption is distinct from
NOT_RUN; real new-object edit tests are not applicable when adoption is zero.

## Required negative checks

Before a real resumed drawing, preserve the unchanged local line-fit and door
partition drift reproductions. Test changed source, ROI/DPI/selection/units,
finite endpoints/intervals, missing evidence, wrong producer, changed upstream
pipeline statement, changed runtime/resource dependency and post-capture
tampering. Test that downstream-only changes cannot reuse old attached results.
The current conservative ink model may still adopt zero complete strokes;
continuation succeeds only if its actual saved old objects and resources remain
exactly preserved. No coordinate rounding, ID rewriting or numeric preservation
tolerance is introduced.

V2 also rejects changed restored output evidence, missing proof internals,
unknown/missing fresh source-check responsibilities, altered actual original-
pixel results, wrong current handles or finite retrace edges, cross-owner
duplicates, stale current plan/producer evidence and nested failed gate details.
Unchanged save bytes and evidence must survive staging-to-publication movement
and an output filename change; absolute task paths are not source identities.
