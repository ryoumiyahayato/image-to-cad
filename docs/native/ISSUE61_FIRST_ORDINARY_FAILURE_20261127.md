## 失败的连带结果

三组已保存短字符需要重放其完整承担路径；结构计划严格比较失败后，三组字符均收到 `SHORT_CONTACT_OWNER_SOURCE_REPLAY_FAILED`。这不能证明字符或承担路径在保存文件中被改坏，也不能将该来源检查标成通过。

局部回绕证明和文字接触路径的共享小段许可依赖上述来源重放。在相关许可未能发放时，原 cold 报告 49 条未认证重复小段。它们是未完成来源认证的连带结果，不应表述为本次新加入了 49 条几何。

圆字参考来源的另一条失败链随后由检查点代理单独做了纯 decision 复现：13 条旧参考整行中只有 1 条完整记录不同，原/new 的 `accepted` 都为真、完整文字相同，差异仅在横短划归一化 proof 的 3 个派生拟合值，量级约 `7.16e-18` 至 `2.22e-16`。原程序仍因整份 decision 不完全相等而拒绝该参考行，6 个圆字参考回退因此失败。此复现不调用 OCR 或图重建；它没有改写原始竞争读法，也不能代替参考来源 proof 的完整续算核验。另两条单行来源的角度严格比较失败由其专项回执说明。

## 可支持的下一步与限制

上述材料支持逐层划定“旧冻结来源 proof 的严格续算验证”范围：实际有限几何、全部来源像素、端点、承担关系、决定和相关依赖仍需验证；原整树 fresh 重放的 FAIL 继续保存。它不支持忽略整个 proof、放宽原生几何、统一舍入、复用一个历史 PASS，或把新的附着阶段 PASS 当成旧来源层的批准。

具体平台或数学库造成历史末位差异的机制尚未证实。本次结论基于原图与冻结计划的实际局部复现及逐字段差异，不据此宣称跨平台确定性已解决。

私有完整材料保留了原始重放结果、规范化 JSON 的全部差异、有限几何逐项相等检查、失败链映射、实际输入和模块哈希。分析脚本早期记录的 9 个 `numpy.float64` 内存类型条目在双方实际 JSON 中没有差异，正式统计已明确排除；原运行记录仍保留。
