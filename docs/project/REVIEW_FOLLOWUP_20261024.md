## 2. 产品目标与当前判断

最高目标继续是：从真实工程 PDF、矢量图或扫描图生成高保真、合理可编辑的二维 CAD，减少核查、描线、重建和修正劳动。质量与劳动节省优先于转换速度。

现有混合处理链、来源责任、独立读回、可撤销校对及有界几何修复值得保留。当前小型数值模型系列的追加投入应暂停：现有真实增益不足以支持继续按原样增加样本、训练步数或配对方案。这是当前预算与证据下的工程决定，不是对学习式方法的普遍否定。

下一步先完成可恢复的源码同步，再定义一个具体交付任务，测量现有链路相对用户实际工作方式的质量与修正负担。现阶段不据外部评审直接晋级实验机制，也不预先把产品改成仅做审计的工具。

## 4. 采纳的评审意见

1. 补现实工作流和端到端转换工具对照。已有 OCR / 公式模型对照不能替代完整 CAD 交付对照。
2. 固定实际运行入口、模块位置与文件内容。分支名、HEAD 或名为 stable 的脚本，都不能单独证明运行的是已验收内容。
3. 将研究继续、人工核查辅助、自动正式改写分开判断。
4. 记录完整交付中的发现、核对、修改、保存与复核劳动；机器时间、AI 操作时间和真人时间分开。
5. 先做有明确输出的小范围诊断，再按结果决定是否投入多人、多页评价。不能把审稿人建议的页数、人时或百分比当成已经验证的强制门槛。

## 5. 不作为已解决方案的建议

- **CTC 后验与语法约束**：可以保留解码时被压缩的候选信息，但并非独立于识别器的新视觉证据。合法整数和合法分数可能同时符合语法；限制字符表也不能证明被强制选出的数字正确。
- **尺寸几何核对**：需要可靠的尺寸对象绑定、单位与局部比例，且排除不按比例、断视图等情况。不能用待核查 OCR 数值反推比例，再用同一比例证明该数值。
- **渲染回验**：可作为离线假设；字体覆盖、取样、遮挡、背景和参数自由度必须受控。像素残差低不自动证明角色、单位或工程语义正确。AUC 阈值不能替代错误采纳率和实际核查成本。
- **几何宽度改为 lineweight**：二者是不同 CAD 属性；可为目标编辑器比较表达合同，不能直接宣称等价替换或原来的合法宽度字段错误。
- **更大模型与自动角色定位**：属于待验证选择；不得把已执行的 Goal22 当作尚未开始，也不得假定其有界定位结果已完成全表达验证。

官方参考： [AutoCAD PDF 输入及限制](https://help.autodesk.com/cloudhelp/2025/CHS/AutoCAD-Core/files/GUID-1202CC8A-364F-4E93-8E86-6F476CD83C72.htm)、[LWPOLYLINE 字段](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-DXF/files/GUID-748FC305-F3F2-4F74-825A-61F04D757A50.htm)、[多段线宽度](https://help.autodesk.com/cloudhelp/2025/ENU/AutoCAD-Core/files/GUID-392BF13C-D9E7-47A8-8E07-435296332279.htm)、[CTC 原始论文](https://www.cs.toronto.edu/~graves/icml_2006.pdf)。

AutoCAD 的 PDF 导入应按输入类型评价：原生对象可导入，SHX 几何需匹配式文字识别；光栅输入不因此自动矢量化。商业对照如使用 Scan2CAD，须记录实际配置；其[增强 OCR](https://www.scan2cad.com/docs/enhanced/)会上传文件，不能把本地与云端构型的结果混用。

## 6. 建议的后续顺序

1. 保全工作区、核对远端差异，将允许公开的源码、实验原型、测试、文档和恢复说明同步到审查分支；完成前不把主分支写成最新验收产品。
2. 从用户实际目标编辑器和一类输入开始，定义一页可交付的完成条件。
3. 用现有工具与现有链路完成小范围同质量诊断，保留正确项保护、漏报、误报、弃判及修正动作。没有真人时只能得到代理证据。
4. 根据缺陷及负担选择一个下一机制；当前优先候选是对象责任与可核对证据。渲染回验、CTC 候选诊断和局部几何一致性均需独立验证，不同时铺开。
5. 获得初步收益后，再扩大独立来源和人工测量。未经完整验收，不把研究代码保存到 GitHub 等同于生产晋级。
