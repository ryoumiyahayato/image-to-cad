## 研发任务的中等规模交付标准

每轮围绕**一类能实际增加图纸内容的问题**，同时处理必要邻接来源、典型反例和真实CAD编辑。正常一次交付至少给出：

1. 具体新增或恢复的**完整可编辑对象**（不是新候选数、OCR次数或 HATCH覆盖）。
2. 同范围真实保存的 DXF、原图/输出对照；能冷读、操作、保存重开，其他旧正确对象保持。
3. 失败项目明确保留原来源并定位待修；禁止硬填文本、误连真实白缝、删除真实短线。
4. 代码变更、少量相关测试、远端 commit SHA；如同步受阻，保存私有可恢复检查点，不等登录超时。
5. 主线合并后删除已无独有内容的临时分支；不必等到整套产品达到 GO 才将已验证代码合并 `main`。

下一批产品内容优先考虑尚未完整恢复的连接线/交汇、门窗符号以及 EBB-3 等**具有可推广性的一类缺口**。三行注释单 MTEXT 与备用 BLOCK 已作有限失败结论：若无与更普遍图块问题相关的直接新证据，不再为这一条注释单独开展多轮兼容性实验。

## 合并和发布的区别

`main` 表示**最新已验证的有效开发版本**。能增进实际CAD且适用CI、原有内容回归通过，即允许正常快进或合并。若当前PR包含失效试验，先隔离它，仅合入经验证的部分，避免用实验失败覆盖原先的正确功能。

正式 Release 仍须独立满足真实输入完整性、目标 CAD 保存/回读、Windows 交付、工程师试用与人工修图时长等产品验收。没有正式工程师计时，继续记 `NOT_RUN`。
