# G1：单一入口收口与恢复语义

本次按用户明确授权，以 [PR #41](https://github.com/ryoumiyahayato/image-to-cad/pull/41)
作为唯一清理合并入口。它包含 [#40](https://github.com/ryoumiyahayato/image-to-cad/pull/40)
的 `f2ad95703cf1ccb0284137bfe7fbc39b137f3217`；#40不再作为第二次源码合并。
合并是否实际发生、main的新SHA及最终分支删除，以GitHub PR事件和执行回执为准，
不能只因文档写了“收口”就记为已经完成。

## 本次实际修正

- 执行协议服从当前用户任务；已授权的实现、修复、验证、合并不再被旧的默认只审计流程拦停。
- README、AGENTS、当前状态和任务区分公开保留基线与私有v8.4，移除重复安排R1/R2的过时指令。
- 旧项目状态移至同目录历史文件，旧日期和结论原文保留；旧清理报告标成当时快照。
- 清理脚本默认核对历史来源提交中的blob、权限及当前远端可达引用；main正常前进、
  合法功能更改或分支由可验证归档替代，不再一律算资料损毁。
- `--strict-current`另行验证本次清理树未改变受保护生产基线。它不能代替后续功能分支的回归测试。
- 加入真实临时Git仓库的正反检查：正常main推进、后续实现更改、分支换成归档可恢复、所有远端恢复引用丢失。

## 复核命令与边界

```bash
git fetch --prune --tags origin
python maintenance/verify_cleanup_20261120.py --remote
# 仅清理变更自身还应运行更严格的当前树检查：
python maintenance/verify_cleanup_20261120.py --strict-current --remote
```

默认检查的“当前树改变”是审查信息，不等于批准代码变化；功能仍须实际回归。
旧清理前后列表和11个删除文件的完整blob/SHA不改，见
[历史执行账本](CLEANUP_EXECUTED_20261120.md)和[原manifest](cleanup_20261120/manifest.json)。

公开入口仍是保留基线；私有v8.4及持续研发分支不自动成为main能力。
维护收口独立于产品GO，整体0.3.0-dev / LOCAL_NO_GO不变。
