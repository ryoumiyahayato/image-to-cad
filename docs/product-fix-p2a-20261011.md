# P2A 中文布局修复

版本保持 `0.3.0-dev`。工作树为 `instrumented-e03`，分支为
`codex/source-support-lifecycle-instrumentation`，HEAD 为 `20b2247fdfdf90fbe10e6daacffe5e339d19cb13`。

根因：`ocr_outline_export.native_text_placement` 正确使用所选 LFF 字体的字形范围和间距，
但此前 `ocr_layout.prepare_candidate_layout` 未将 OCR 框中的空白边缘与实际墨迹范围区分。
整行按检测框高度拟合后，中文字被拉高，并通过宽度系数压回原框。
源 PDF 第 1/2/3 页的保存图和直接 PDF 渲染均复现该问题。
PDF 无原生可提取文字，因此没有使用原生文字替换 OCR 内容。

|---|---|---|---|---|---|
| W01 施工图 | 82×42 | 102×60 | 84×44 | 5.0649 → 3.7143 | 0.4923 → 0.5529 |
| W02 施工图 | 53×27 | 69×41 | 55×29 | 6.1092 → 4.3211 | 0.4874 → 0.5492 |
| W03 施工图 | 42×22 | 56×34 | 44×24 | 6.2635 → 4.4213 | 0.4770 → 0.5309 |
| W02 3.1 每层按防火分区增加信号阀、水流指示器报警； | 420×29 | 431×37 | 422×31 | 5.2171 → 4.3711 | 0.4573 → 0.5344 |

新显示框由现有源图掩膜取得，保留一像素边缘余量，限制在检测框及表格单元内。
实际源墨迹与经过规则清理的范围在上述四处一致。
只处理通过现有源覆盖检查、未经人工指定布局的水平中文及中英文混排；
不改变 OCR bbox、逐字框、字符串、数字复核或几何保护区域。
不确定、倾斜、人工指定及单数字布局保持原值。
`ocr_fast.py` 在后续源覆盖检查失败时恢复原 quad；表格裁剪保留已收紧的显示框。
处理缓存标识更新；旧结果与旧缓存均保留。

修改：`app/ocr/ocr_layout.py`、`app/ocr/ocr_fast.py`、`app/core/processing.py`。
新增局部用例：`tests/test_source_text_layout.py`。
字体、字体安装目录、文字写入器和已有几何实现未修改。

输出位于 `local-artifacts/product-fix-p2a-20261011/`。
三份完整 DXF 复用保存的几何，只通过现有生产 TEXT 写入器回放上述四处布局。
全部 TEXT 字符串和实体类型数量保持不变；其他实体的属性和 LWPOLYLINE 顶点保持不变。
插入点按源墨迹中心与实际字体可见范围重新计算，仍为左侧基线对齐。
LINE、LWPOLYLINE、CIRCLE 及所有相对 IMAGE 引用保留，修订号仍为 `1`。
局部默认预览与实际导出的 TEXT 一致，未用源图覆盖字形。
